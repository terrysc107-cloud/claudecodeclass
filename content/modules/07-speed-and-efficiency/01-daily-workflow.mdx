The developers who get the most out of Cursor are the ones with a consistent daily system. Without a system, you're using AI reactively — reaching for it when you're stuck instead of building it into every part of how you work.

## Morning Warmup (10 minutes)

Start every dev session with a brief Chat session to rebuild context:

```
@yesterday-changed-files I'm picking up where I left off.
Here's what I was working on: [brief description].
Review these recent changes and tell me:
1. What's done and what's still incomplete?
2. Are there any issues or inconsistencies I should address?
3. What should I tackle first today?
```

This gets you oriented faster than reading your own code and often surfaces things you forgot about.

<Callout type="tip">
At the end of each day, leave a breadcrumb comment at your stopping point: `// TODO: next session — add validation for the edge case where user has no payment method`. When you pick up the next morning, your warmup prompt can reference this comment and Cursor will immediately understand the context.
</Callout>

## Task Batching

Group your work by type, not by project:

- **Composer sessions** for new feature work (requires deep focus)
- **Chat + Cmd+K** for debugging and small fixes (can be interrupted)
- **Review cycles** for reading diffs and accepting changes (can be interrupted)

Don't mix deep Composer work with interruptions. Set aside focused blocks.

## The Decision Rhythm

AI gives you more decisions to make, not fewer. You're reviewing diffs, accepting or rejecting, following up. Build a rhythm:

1. Write prompt / start session
2. Let it run (don't hover — do something else for 30 seconds)
3. Review output completely
4. Accept what's right, reject what isn't
5. Follow up in the same session if needed
6. Commit checkpoint

Resist the urge to stop and read the diff line-by-line as it streams. Let it finish, then review the whole thing.

## End-of-Day Commit Ritual

Before you close the laptop:

1. Commit anything meaningful (even if it's WIP)
2. Run `git diff HEAD` and ask Chat to summarize it
3. Leave your breadcrumb comment for tomorrow
4. Close all Composer sessions (stale context isn't helpful the next day)

<Callout type="info">
A committed WIP is better than uncommitted work. You can always amend or reset, but you can't recover code that wasn't saved. And the commit message — even if it's "WIP: settings page scaffolding" — gives you a useful anchor for the morning warmup.
</Callout>

## Handling Interruptions

When you get pulled away mid-Composer session:

1. Finish the current step (don't abandon mid-generation)
2. Add a comment explaining where you stopped
3. Commit if there's something worth saving
4. When you return, start with a brief Chat warmup before resuming

The biggest productivity killer is resuming a session cold, trying to remember where you were, and spinning for 20 minutes. The warmup eliminates this.

<KeyPoint>Developers who get the most from AI have a consistent daily system. A morning warmup that rebuilds context and an evening commit ritual that preserves it are the two habits that compound the fastest.</KeyPoint>
