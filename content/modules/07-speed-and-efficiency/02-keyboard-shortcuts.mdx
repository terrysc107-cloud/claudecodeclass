Claude Code lives in your terminal, which means your speed tools are slash commands, shell aliases, and keyboard shortcuts native to your terminal emulator. Learn these and you'll move significantly faster.

## The Core Slash Commands

| Command | What it does | When to use it |
|---------|-------------|----------------|
| `/help` | Show all available commands | When you forget something |
| `/clear` | Reset the conversation entirely | Starting a new task, switching context |
| `/compact` | Summarize conversation to save tokens | When context grows long mid-task |
| `/status` | Show current session info | Check what Claude knows about the project |
| `/memory` | View and edit memory/CLAUDE.md | Update persistent project context |
| `/model` | Switch the active model | Change between Sonnet, Haiku, Opus |
| `/cost` | Show token usage for this session | Monitor spend during a long session |

<Callout type="tip">
`/compact` is one of the most valuable commands in your arsenal. When you're deep in a long debugging or feature session, token count climbs fast. `/compact` compresses the conversation into a summary, preserving what matters and shedding the noise. Use it before the context window becomes a bottleneck, not after.
</Callout>

## /clear vs /compact: Know the Difference

These two commands are easy to confuse but serve very different purposes:

- **`/clear`** — wipes everything. Fresh start. Use this when you're done with a task and moving on to something unrelated. Claude retains nothing from the previous session.
- **`/compact`** — trims the conversation while keeping the useful parts. Use this mid-task when the session is getting long but you still need the context. Claude summarizes what's happened and continues with a lighter footprint.

When in doubt: if you're continuing the same task, use `/compact`. If you're starting something new, use `/clear`.

## Terminal Keyboard Shortcuts

Claude Code runs in your standard terminal, so these shell shortcuts apply everywhere:

| Shortcut | Action |
|----------|--------|
| `Ctrl+C` | Cancel current operation or interrupt Claude mid-response |
| `Ctrl+L` | Clear the terminal screen (keeps session active) |
| `Up arrow` | Cycle through previous prompts |
| `Ctrl+R` | Reverse-search your prompt history |
| `Ctrl+A` | Jump to beginning of current line |
| `Ctrl+E` | Jump to end of current line |
| `Ctrl+W` | Delete the last word typed |
| `Ctrl+U` | Clear the entire current line |

The `Up arrow` history cycling is underused. When you find a prompt pattern that works well — a debugging prompt, a refactor prompt, a review prompt — you can recall and reuse it quickly.

## Shell Aliases That Save Time

Add these to your `.zshrc` or `.bashrc`:

```bash
# Launch Claude in the current project
alias cc="claude"

# Launch Claude with a quick one-off prompt
alias cq="claude -p"

# Start a fresh session explicitly
alias cclear="claude --no-continue"

# Common workflow starters
alias cdebug='claude -p "Review recent changes and identify any bugs or issues"'
alias creview='claude -p "Review my staged changes and give feedback before I commit"'
alias cdocs='claude -p "Generate documentation for the functions I just wrote"'
```

Run `source ~/.zshrc` after adding these, or open a new terminal.

## Multi-line Prompts in the Terminal

For longer prompts, use a heredoc so you don't have to cram everything onto one line:

```bash
claude << 'EOF'
I need to refactor the authentication module.
Current state: JWT tokens stored in localStorage.
Goal: Move to httpOnly cookies with refresh token rotation.
Constraints: Don't break the existing session for logged-in users.
EOF
```

This is much easier to read and edit than trying to stuff a complex prompt onto a single line.

<Callout type="info">
The most important habit to build is reaching for `/compact` before a session gets unwieldy. Long sessions with too much context start producing worse output — the model has to attend to too many things. A clean, compact context with a clear current state almost always outperforms a bloated one.
</Callout>

## The Workflow Triggers

Build these patterns into muscle memory:

- Task is done, moving on → `/clear`
- Session getting long but still working → `/compact`
- Need to change models → `/model`
- Wondering what this is costing → `/cost`
- Forgot a command → `/help`
- Want to update project context → `/memory`

## Piping and Shell Integration

Claude Code integrates with standard Unix piping, which opens up powerful one-liners:

```bash
# Pipe a file's contents into Claude
cat src/auth.ts | claude -p "Find any security issues in this code"

# Pipe git diff into Claude for a commit message
git diff --staged | claude -p "Write a concise commit message for these changes"

# Pipe test output to get debugging help
npm test 2>&1 | claude -p "These tests are failing. What's wrong?"
```

This makes Claude Code feel native to the Unix environment rather than a separate tool you have to switch to.

<KeyPoint>A handful of slash commands used consistently beats memorizing everything at once. Start with /compact and /clear to manage context, build your shell aliases for common workflows, and let the rest follow naturally as you develop your own patterns.</KeyPoint>
