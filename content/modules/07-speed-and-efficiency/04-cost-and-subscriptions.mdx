Claude Code has real costs, and understanding the pricing structure lets you get maximum value without surprises on your API bill. The good news: the economics almost always favor using it more, not less.

## Two Ways to Pay

**Anthropic API (pay per token)**
You pay for exactly what you use. No monthly fee, but costs scale directly with usage. Best for:
- Occasional or irregular use
- Experimenting to see how much you actually use it
- Teams that want usage tracked per project

**Claude.ai Pro or Max subscription**
A monthly flat fee that includes Claude Code usage. Best for:
- Daily heavy users who want predictable costs
- Developers using Claude Code as a primary tool, not an occasional one
- Anyone who gets frustrated mentally tracking token spend

**Anthropic Max plan** is the tier designed specifically for heavy Claude Code users. If you're running long multi-file sessions regularly, doing daily coding work, or building production software full-time with Claude Code, Max gives you the high usage limits you need without per-token anxiety.

<Callout type="tip">
If you're just starting out, begin with API access and run it for two weeks. Look at your actual usage. If your monthly API cost is approaching or exceeding the Pro subscription price, switch to Pro. If it's approaching Max levels, go Max. Let your actual usage pattern determine the right tier — don't guess.
</Callout>

## How Tokens Actually Add Up

Understanding what costs the most helps you be intentional about usage:

| Operation | Token impact | Notes |
|-----------|-------------|-------|
| Short back-and-forth questions | Low | A few hundred tokens per exchange |
| Long session with file context | Medium | Accumulates over the conversation |
| Large file included in context | Medium-high | Each file read adds tokens |
| Long debugging session | High | Many rounds of back-and-forth |
| Multi-file refactor session | High | Large input + large output |

The expensive operations are long sessions where Claude holds a lot of context simultaneously. The fix is proactive context management — not avoiding Claude Code.

## /compact: Your Cost Control Tool

The single most effective way to manage cost mid-session is `/compact`. When a session has been running long:

```
/compact
```

Claude summarizes the conversation into a compact representation, preserving the decisions made, the current state of the work, and the relevant context — while shedding the verbose back-and-forth that no longer matters. Token count drops significantly. You continue in the same session.

Use `/compact` before you need it, not after you've hit a wall. A good rule: if you've had more than 15–20 exchanges in a session, consider compacting.

<Callout type="info">
Think of /compact like saving a checkpoint in a video game. You don't wait until you're about to die. You save when things are going well so you have a clean state to continue from. Compact your session when it's productive, not when it's already struggling under the weight of too much context.
</Callout>

## Model Selection

Claude Code gives you access to different Claude models. Not every task needs the most powerful (and most expensive) one:

| Task | Appropriate model |
|------|------------------|
| Quick questions, simple refactors, generating comments | Haiku (fastest, cheapest) |
| Debugging, code review, moderate complexity | Sonnet (balanced) |
| Complex architecture, multi-file refactors, hard problems | Opus (most capable) |

Switch models with `/model` during a session. Starting a session in Haiku for exploration and switching to Opus for the hard part is a legitimate cost-optimization strategy.

## Write Focused Prompts

Vague prompts produce longer back-and-forth, which costs more. Specific prompts produce better output on the first try, which costs less:

**Vague (expensive):**
```
fix my auth
```

**Specific (efficient):**
```
The login endpoint returns 401 when the token is valid but expired.
Refresh token logic is in /lib/auth.ts. The issue is in the token
validation on line 47 — it's not calling refreshToken() when
shouldRefresh() returns true. Fix the validation flow.
```

The specific prompt costs more tokens to write, but the session is likely to be 3–5 exchanges shorter because Claude has enough context to get it right immediately.

## The ROI Calculation

The right way to think about Claude Code costs is not "how do I minimize spend" but "what is the return on this spend."

A developer billing $100/hour who avoids one hour of manual work with a $2 Claude session has a 50x ROI on that session. The question is never whether to use Claude Code — it's whether you're using it in ways that actually produce that ROI.

Use it heavily on work that creates value. Be thoughtful about long exploratory sessions that don't produce concrete output.

<KeyPoint>The Max subscription exists for developers who use Claude Code seriously every day. Start with API billing to understand your actual usage, then choose the plan that matches your patterns. Use /compact aggressively to manage session costs, and match model choice to task complexity.</KeyPoint>
