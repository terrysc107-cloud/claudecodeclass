The first time you drop into a project with Claude Code, you have a guide that can read the entire codebase with you. Rather than spending hours tracing files manually, you can ask Claude to explain the architecture, map the data flow, and flag inconsistencies — before you write a single line.

## Starting a Session

Navigate to the project root in your terminal and run:

```bash
cd my-project
claude
```

That's it. Claude Code starts an interactive session in your current directory. It can read any file, run bash commands, and make edits — all through natural language.

<Callout type="info">
Claude Code operates on your actual filesystem. It can read every file in your project directory, run your test suite, and check git history. You're not copying code into a chat window — you're working directly inside the project.
</Callout>

## Get Oriented Before You Edit

Resist the urge to start making changes immediately. Start with a few orientation questions:

```
Give me a high-level overview of this project.
What are the main modules and how do they relate to each other?
```

Then drill into specific areas:

```
Where is the authentication logic handled?
How does data flow from the API to the UI?
What's the database schema for user accounts?
```

Claude will read the relevant files and explain them in plain language. This orientation step takes five minutes and saves hours of confused exploration.

## Finding What Already Exists

Before adding anything, ask what's already there:

```
Is there already a utility for formatting currency?
What components exist for displaying error states?
How are API errors handled across the app?
```

You'll avoid creating duplicates, and your new code will integrate cleanly with the existing patterns rather than working against them.

## Setting Up CLAUDE.md

For any project you work in regularly, create a `CLAUDE.md` file at the root. Claude reads this automatically at the start of every session:

```markdown
# Project Context

This is a Next.js app with a Supabase backend.

## Commands
- `npm run dev` — start local server
- `npm test` — run Vitest tests
- `npm run build` — production build

## Conventions
- API routes live in `app/api/`
- Shared types are in `types/`
- Use the existing `lib/supabase/server.ts` for all database access
```

This replaces the need to re-orient Claude at the start of every session.

<Callout type="tip">
When taking on a client project, run through these questions before your first call with the client: "What are the riskiest parts of this codebase?" and "What patterns are used inconsistently?" You'll show up with insight that would normally take a week to develop.
</Callout>

## Client Projects

This workflow is especially valuable on client codebases. You can orient yourself in minutes instead of days. Ask Claude to explain the architecture, identify the main data flows, and flag any areas that look fragile or inconsistent — then walk into the engagement with a clear picture of what you're working with.

<KeyPoint>Run `claude` from your project directory and ask for a high-level overview before you start editing. The 5-minute orientation saves hours of confused exploration and prevents changes in the wrong place. Add a CLAUDE.md to make that context permanent.</KeyPoint>
