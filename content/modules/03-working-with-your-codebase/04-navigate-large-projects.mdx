Large codebases are where AI assistance has the highest leverage — and where it's also easiest to get lost. A few navigation strategies keep you productive regardless of project size.

## Scope Your Context

`@codebase` searches everything, but you don't always need everything. When you know where the relevant code is, scope it:

- `@src/payments` — searches only the payments module
- `@components/forms` — searches only form components
- `@app/api` — searches only API routes

Narrower scope = faster, more accurate responses.

<Callout type="tip">
Think of folder @-mentions like namespaces. If you're working in the billing module, prefix your Chat questions with `@src/billing` to keep Cursor focused. You'll get more relevant answers and avoid getting pulled toward unrelated code in other parts of the project.
</Callout>

## Symbol Navigation

Cursor inherits VS Code's Go to Definition (F12) and Find All References (Shift+F12). Use them:

- **F12** on a function name → jumps to the definition
- **Shift+F12** on a function → shows every call site
- **Cmd+P** → file search
- **Cmd+Shift+O** → symbol search within a file

These are faster than grepping or manual searching for specific identifiers.

## The .cursorignore File

For large monorepos or projects with generated code, create a `.cursorignore` file in the root:

```
node_modules/
.next/
dist/
generated/
coverage/
```

This keeps the index focused on your actual source code and improves Chat response quality. Generated code and dependencies create noise that dilutes the signal.

## Ask What's Related

When starting work on a feature, ask Cursor to map the territory:

```
@codebase What files are most likely to be affected if
I add a subscription tier system to this app?
```

```
@src/users What other parts of the codebase depend on
the User model?
```

<Callout type="info">
For client projects specifically, this "blast radius" mapping is worth doing before every significant change. It takes 30 seconds and prevents the "I didn't know that was connected to this" conversations with clients after something breaks.
</Callout>

## Indexing Settings

In Cursor Settings → Features → Codebase Indexing, you can:

- Force a re-index if the code changed significantly
- Check what's currently indexed
- Configure automatic re-indexing on save

Re-index after pulling large changes from main or after switching branches on a complex project.

<KeyPoint>@codebase turns Cursor into a search engine for your entire project. Scope it to folders for speed and accuracy — you don't need to search everything when you know where the code lives.</KeyPoint>
