Claude Code has direct access to a bash shell. It can run commands, execute scripts, read output, and take follow-up actions based on results — all as part of a conversation. This is one of its most powerful capabilities and one that deserves a clear mental model.

## How the Bash Tool Works

When a task requires running a command, Claude Code uses its bash tool to execute it in a shell in your project directory. The output — stdout, stderr, exit codes — comes back to Claude Code, which can then reason about it and decide what to do next.

This is not simulated. Commands actually run on your machine. A `git commit` commits. An `npm install` installs packages. A `rm` deletes files.

```
> Run the test suite and tell me which tests are failing.
```

Claude Code runs `npm test` (or whatever your test command is), reads the output, identifies the failing tests, and reports back — often with an explanation of why they're failing based on the code it has already read.

## What It Can Do

Common and useful bash tool uses:

- Running test suites and interpreting results
- Installing dependencies after modifying package.json
- Running linters and auto-fixers
- Checking git status and diff before committing
- Running database migrations
- Starting a dev server and checking for startup errors
- Searching for patterns with `grep` or `find`
- Running build commands and diagnosing output

```
> Install the zod package and add it to package.json, then update the
  user validation in lib/validation.ts to use it.
```

Claude Code runs `npm install zod`, confirms the install succeeded, then makes the code changes.

<Callout type="tip">
You can ask Claude Code to run commands you'd otherwise have to look up. "Run the linter and fix the auto-fixable issues" or "Check if there are any TypeScript errors and explain what's causing them" are faster than running the commands yourself and reading the output manually.
</Callout>

## Safety Guardrails

Claude Code is designed to be cautious with consequential actions. Before running commands that could cause data loss, make permanent changes, or affect production systems, it will describe what it's about to do and ask for confirmation.

Specifically, it will pause before:

- Deleting files or directories
- Running commands with `--force` or similar override flags
- Operations that affect git history (rebase, reset)
- Anything involving production environment variables or credentials
- Network requests that write to external services

For routine development tasks — running tests, installing packages, running builds — it proceeds without interruption.

<Callout type="warning">
Claude Code runs with the same permissions as your terminal session. It can do anything you can do. Treat it accordingly: don't run it as root, be thoughtful about what environment variables are in scope, and don't use it to handle credentials you wouldn't want exposed in a shell history.
</Callout>

## Interpreting Command Output

One of the most useful patterns is asking Claude Code to interpret complex output for you:

```
> Run `npm audit` and explain which vulnerabilities are actually
  exploitable given how we use these packages, and which ones I
  can safely ignore.
```

```
> Run the build and explain what these TypeScript errors mean and
  what I need to change to fix them.
```

Claude Code doesn't just relay output — it reasons about it in the context of your specific codebase and gives you actionable guidance.

## Combining Bash and File Edits

The real power is when bash commands and file edits work together in a single task:

```
> Run the tests. For each failing test, find the relevant source code
  and fix whatever is causing the failure. Then run the tests again
  to confirm they pass.
```

Claude Code runs tests, reads the failures, opens the relevant files, makes targeted edits, runs tests again, and iterates until everything passes — or until it hits something that requires a judgment call from you.

## Scripting and Automation

Claude Code also works in non-interactive mode, making it useful for automation:

```bash
claude -p "Run the test suite and output a JSON summary of pass/fail counts"
```

This makes it composable with CI pipelines, pre-commit hooks, and shell scripts that need AI-assisted analysis or generation as a step.

<KeyPoint>The bash tool makes Claude Code an active participant in your development process, not just a code suggester. It runs commands, reads results, and takes follow-up action — with safety checks for anything consequential.</KeyPoint>
