`CLAUDE.md` is a plain text file in your project root that tells Claude Code how to behave for that specific project. It's the difference between Claude writing generic code and Claude writing code that matches your stack, your conventions, and your client's requirements. Claude reads this file automatically at the start of every session.

## What Goes in CLAUDE.md

The file is a set of instructions in plain language. Claude reads it before responding to any request in that project:

```
You are an expert Next.js developer working on a SaaS application.

## Tech Stack
- Next.js 15 App Router with TypeScript
- Supabase for database and auth
- Stripe for payments
- Tailwind CSS v4 for styling
- Vitest for testing

## Conventions
- All React components use named exports (no default exports)
- API routes use the pattern in /app/api/example/route.ts
- Database queries go through /lib/db.ts, never inline
- Error handling uses the Result type from /lib/result.ts
- All monetary values are stored and passed in cents (integers)

## Style
- Prefer early returns over nested if statements
- Functions should be pure where possible
- Add JSDoc for all exported functions
- Keep components under 150 lines — extract if larger

## Do Not
- Use any 'any' TypeScript types
- Write raw SQL — use the query helpers in /lib/db.ts
- Add new dependencies without asking first
```

<Callout type="tip">
Start your `CLAUDE.md` with a brief description of what the project is and who the user is. Context about the business problem helps Claude make better judgment calls about tradeoffs. "This is a B2B invoicing SaaS for small contractors" leads to different decisions than "this is a consumer entertainment app."
</Callout>

## Per-Client Rules

For freelance or agency work, customize `CLAUDE.md` per client project:

```
## Client Context
Client: Acme Corp — a mid-size construction company
This codebase is maintained by a small in-house team of non-experts.
Write defensive code with extra comments. Avoid clever patterns.
Prefer verbose clarity over brevity.
```

This produces code that the client's team can actually maintain after you're done — which is a quality signal that wins referrals.

## Project-Level vs. Global Instructions

Claude Code supports global instructions in `~/.claude/CLAUDE.md` that apply to every project. Use global instructions for your personal preferences:

```
Always explain what you changed and why at the end of each response.
Prefer functional patterns where appropriate.
Never use var — always const or let.
```

Project-level `CLAUDE.md` files are read in addition to your global instructions, and their more specific rules take precedence when there is any conflict.

<Callout type="info">
Build a library of `CLAUDE.md` files — one per stack you work with regularly. A Next.js + Supabase instructions file, a Python FastAPI instructions file, a React Native instructions file. When you start a new project, copy in the relevant base instructions and customize. This saves setup time and ensures consistency across projects.
</Callout>

## Iterating the Instructions

Add to `CLAUDE.md` whenever you catch Claude making a mistake you've corrected before. If you keep telling it "don't do X" in conversation, add "Do not X" to the instructions file. Over time, your `CLAUDE.md` becomes a tuned configuration for how you work — a precise record of every lesson learned on that project.

You can also include project-specific commands to run for testing, linting, and building. Claude will use these automatically when it needs to verify its work:

```
## Commands
- Run tests: npm test
- Lint: npm run lint
- Build: npm run build
- Dev server: npm run dev
```

<KeyPoint>CLAUDE.md is the difference between a generic AI and one that knows your stack. A well-written instructions file eliminates the need to repeat yourself, reduces cleanup time, and makes your output consistent across an entire project.</KeyPoint>
