Scripts are one of the most underrated revenue streams for developers. A 50-line Python script that saves a client 5 hours per week is worth $500–$2,000 as a one-time delivery — and the same client will pay you again when they need updates or a new automation.

## The Prompt Pattern for Scripts

Describe the business problem in plain language:

```
Build a Python script that:
- Reads from a Google Sheets spreadsheet (via the Sheets API)
  containing customer orders (columns: order_id, customer_email,
  product, quantity, ship_date)
- Filters for orders where ship_date is today
- Sends a shipping notification email to each customer
  via SendGrid with their order details
- Logs which emails were sent to a CSV file with timestamp
- Runs without manual intervention (suitable for a cron job)

Use environment variables for all API keys.
Include a requirements.txt.
```

<Callout type="tip">
The most valuable automations are the ones that touch spreadsheets, emails, and reports — because those are the manual tasks that eat the most time at small and mid-size businesses. If a business has a person whose job involves a lot of copy-paste between systems, that's a $500–$2,000 automation waiting to be built.
</Callout>

## High-Value Automation Niches

**Data pipelines:**
- Pulling data from one system, transforming it, writing to another
- CSV → database imports on a schedule
- Syncing records between two SaaS tools via API

**Report generation:**
- Weekly PDF reports generated from database queries
- Automatically emailed to stakeholders every Monday morning
- Formatted with charts and tables

**Notification systems:**
- Alert when inventory drops below a threshold
- Notify a team when a payment is overdue
- Daily summary of key metrics via Slack or email

**Spreadsheet automation:**
- Clean and validate data from form submissions
- Merge multiple spreadsheets on a schedule
- Auto-calculate formulas and update a master sheet

## Cursor's Script Workflow

1. **Describe the input and output** in your Composer prompt (what does the script read? what does it produce?)
2. **Reference any existing API docs** via `@web` or by pasting in key documentation
3. **Review the generated script** — read every line, especially the API calls and error handling
4. **Test with real data** — small sample first, full dataset after

<Callout type="info">
Ask Cursor to include comprehensive error handling and logging in every script. Scripts that run on a schedule at 2am without anyone watching need to fail loudly: write to a log file, send a failure email, or both. A silent failure in an automation is worse than no automation at all.
</Callout>

## Pricing Scripts

Anchor your price to the value saved, not the time spent:

- Script saves 5 hrs/week at $30/hr labor cost = $150/week saved = $7,800/year
- Charging $1,000–$2,000 for that script is a 4–8x ROI for the client in the first year alone

Most clients will see that math and say yes immediately.

## Recurring Revenue from Scripts

After delivery, offer a support/maintenance package:

- $100–$300/month to keep the script running, handle API changes, and make small adjustments
- Position it as "we monitor and maintain so you don't have to"

One automation with a maintenance retainer is $1,200–$3,600/year of recurring revenue.

<KeyPoint>A 50-line script that saves a client 5 hours/week is worth $500–$2,000. Price on ROI, not time spent. Then offer a maintenance retainer and turn a one-time project into recurring income.</KeyPoint>
